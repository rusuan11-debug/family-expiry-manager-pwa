# 家庭保质期管家 PWA

面向单台 iPhone 的本地优先 PWA。GitHub Pages 只托管公开程序文件；商品、照片和冰箱记录保存在当前设备 IndexedDB。应用不使用云数据库、付费 API、统计 SDK 或运行时 CDN。

## 当前功能（V1.2.0）

- 首页：普通商品的总数、临近到期、已过期，以及冰箱食物的临期摘要。
- 商品管理：四类商品、搜索、增删改查、购买日期、生产日期、保质期、包装到期日、开封后期限。
- 商品照片：仅保留商品封面照片，支持相机拍照和相册导入。
- 条形码扫描：本地打包 ZXing 扫描 EAN-13、EAN-8、UPC-A、UPC-E、Code 128、ITF 等常见条码。
- 条码资料查询：扫描或输入条码后，联网查询 Open Facts 的统一条码入口（product_type=all），尝试从 Open Food Facts、Open Beauty Facts、Open Products Facts 获取名称、品牌、配料、过敏原和营养资料；按数据库类型和商品分类词自动选择本应用分类，资料可修改后保存到本机。
- 冰箱管理：独立记录食物名称、分类、冷藏/冷冻、数量、放入日期、保存期限/到期日和备注。冰箱记录与普通商品分开保存。
- 设置：仅保留完整备份导出和恢复。
- 离线：应用外壳和扫码引擎可缓存；已经保存的商品与冰箱资料可离线查看和编辑。首次扫码查询商品数据库仍需要联网。

## 明确边界

- 条码只用于识别商品编号，不包含商品配料、营养或保质期。Open Food Facts 数据由社区贡献，可能缺失、错误或不完整；商品包装标签优先。
- 扫码查询会把条形码发送到 Open Food Facts；不会上传本机商品记录或照片。该查询服务免费读取，但有服务端频率限制，并不保证永久可用。
- Open Food Facts 当前推荐新接入使用 API v3；本应用调用 v3.6 的按条码读取接口。数据库内容按其 ODbL / DbCL 等许可要求使用，商品照片有独立许可。
- 本版不做自动健康/医疗风险结论；配料、过敏原和营养信息仅作为商品资料展示，需以包装及权威标准核对。
- 冰箱保存期限是家庭记录提醒，不代表对所有食物的食品安全保证。
- 不支持两台手机同步；每台设备有独立本地数据库。
- 不提供应用关闭后的定时推送提醒。
- 不会自动识别生产日期或配料表照片；生产日期、保质期仍由用户手动录入或根据包装日期填写。
- 旧版商品中的生产日期照片、配料表照片和历史字段不会被程序主动清除；新版界面不再显示这些照片入口。原商品记录和商品封面照片继续使用同一 IndexedDB 数据库。
- 不读取旧 Scriptable P0/P1 数据目录。

## 数据备份

备份文件包含普通商品、商品照片和冰箱食物记录。恢复旧版备份时，如果备份中没有冰箱记录，冰箱列表会恢复为空。建议在升级前先导出一次完整备份，并妥善保存在 iPhone「文件」或电脑中。

不要把个人备份 JSON 或商品照片上传到公开 GitHub 仓库。

## 发布

仓库使用 GitHub Actions 自动发布 GitHub Pages。源码更新到 main 后，工作流会：
1. 装配静态 PWA 文件；
2. 运行 JavaScript 语法检查；
3. 从 npm 安装开源 ZXing 扫码依赖并打包为同源静态文件；
4. 部署到 GitHub Pages。

网站地址：

https://rusuan11-debug.github.io/family-expiry-manager-pwa/

在 iPhone Safari 打开网址，选择「分享」→「添加到主屏幕」，并启用「作为网页 App 打开」。

## 开发文件

- `index.html`：PWA 入口
- `app.js`：页面、商品、冰箱、条码查询与交互
- `barcode.js`：ZXing 扫码模块源码
- `core.js`：日期计算和商品数据模型
- `storage.js`：IndexedDB、本机备份与恢复
- `styles.css`：手机界面
- `sw.js`：离线缓存
- `manifest.webmanifest`：主屏幕网页 App 配置
- `assets/`：应用图标
